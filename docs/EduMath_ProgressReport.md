Разработать прототип веб-приложения, которое показывает образовательные курсы, позволяет искать их и предоставляет персонализированные рекомендации. ## 3. Data Engineering — выполненная работа

Выбран набор **`pymlex/openedu-courses`** на Hugging Face. Получены три исходных файла:

| Файл | Размер | Назначение |
| --- | --- | --- |
| `openedu_courses_base_info.csv` | 1 189 строк, 6 столбцов | Базовые сведения о курсах |
| `openedu_courses_full_info.csv` | 1 189 строк, 26 столбцов | Расширенные описания и признаки курсов |
| `openedu_groups_map.csv` | 374 строки | Справочник направлений обучения |

Проведён первичный аудит: ID курсов уникальны и совпадают в двух таблицах; проверены текстовые поля, даты, длительности, направления и пропуски. В наборе **1 072 русскоязычных** и **117 англоязычных** курсов от **13 университетов**. Для повторного аудита подготовлен `data/src/data_audit.py`.

Выявленные особенности данных:

- один курс может относиться к нескольким направлениям; для интерфейса и ML ещё предстоит согласовать правило их представления;
- у 88 курсов направления не указаны;
- в отдельных текстовых полях имеются пропуски и технические значения;
- пропуски в `certificate` нельзя без проверки смысла поля считать подтверждённым отсутствием сертификата.

**Не завершено:** очистка по согласованным правилам и подготовка итогового `courses.csv` для общего использования Backend и ML.

## 4. Machine Learning — выполненная работа

В `ml/main.py` реализован класс **`CourseRecommender`** и функция:

```python
recommend_courses(user_id=1, top_k=10)
```

Реализованы:

1. **Контентные признаки:** TF-IDF по названиям, описаниям, компетенциям, результатам обучения, университетам и категориям.
2. **Пользовательский профиль:** агрегирование векторов курсов из истории взаимодействий с учётом веса действий.
3. **Ранжирование:** косинусное сходство с профилем пользователя в сочетании с дополнительным эвристическим показателем по данным курса.
4. **Холодный старт:** при отсутствии истории используется эвристическая оценка курсов.
5. **Диверсификация:** ограничение количества курсов одной категории в рекомендациях.
6. **Единый формат вывода:** `course_id`, `title`, `category`, `score`.

Модуль использует `pandas`, `numpy`, `scikit-learn` и исходные файлы OpenEdu. Директория данных задаётся через `OPENEDU_DATA_DIR`; в текущем коде значение по умолчанию — `/data/raw`.

**Текущие ограничения:** взаимодействия пользователей пока заданы тестовой заглушкой для двух профилей; соединения с реальной базой данных нет. В предоставленном коде **не реализована матричная факторизация ALS/SVD**. Метрики Precision@k и NDCG также пока не представлены. Текущий алгоритм не следует описывать как уже реализованную коллаборативную фильтрацию.

## 5. Backend + MLOps — выполненная работа

Сервер создан на **Python + FastAPI**, запуск — через Uvicorn. Реализован базовый API:

| Эндпоинт | Назначение | Состояние |
| --- | --- | --- |
| `GET /courses` | Возвращает список курсов | Работает с 10 тестовыми курсами |
| `GET /courses?search=...` | Поиск по названию | Подготовлен в улучшениях Backend |
| `GET /courses?category=...` | Фильтрация по категории | Подготовлен в улучшениях Backend |
| `GET /recommendations?user_id=1` | Возвращает топ рекомендаций | Работает на тестовой выдаче, **не использует ML** |

Оба основных запроса возвращают **JSON-массив**. Настроен CORS для локального Frontend (порты 3000 и 5173). Подготовлены файлы зависимостей, инструкция запуска, **6 автоматических тестов** (по отчёту Backend: все 6 прошли) и `Dockerfile`. Образ Backend собирался и проверялся отдельно; **полное Docker-развёртывание всей системы ещё не выполнено**.

**Не завершено:** загрузка реального `courses.csv` в БД, подключение `recommend_courses()`, хранение действий пользователей и проверка полной системы.

## 7. Архитектура и согласованный интерфейс

```text
OpenEdu CSV ───────────► Data Engineering
                              │
                              ▼
                      Общие данные курсов
                         │          │
                         ▼          ▼
                   ML-рекомендатель   Backend / FastAPI
                         │          ▲
                         └──────────┘  (интеграция впереди)
                                    │ HTTP / JSON
                                    ▼
                              React Frontend
```

**Текущий контракт API:** для курса используются `course_id`, `title`, `category`, для рекомендации дополнительно `score`. Идентификаторы должны совпадать во всех подсистемах. Для рекомендаций возвращается массив объектов без внешней обёртки `data` / `items`.

Пример структуры ответа (значения условные):

```json
[
  {
    "course_id": 101,
    "title": "Пример образовательного курса",
    "category": "Программирование",
    "score": 0.85
  }
]
```

`score` — внутренний численный балл модели, **не процент совпадения и не вероятность**.
