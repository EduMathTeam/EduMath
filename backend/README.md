
# Backend — EduMath

Backend для рекомендательной системы образовательных курсов EduMath.

Используемые технологии:
- Python
- FastAPI
- SQLite
- ML-модель рекомендательной системы
- Docker
- Pytest

## 1. Реализованные возможности

- Загрузка 1189 реальных курсов OpenEdu.
- Хранение курсов в SQLite.
- Получение списка курсов через API.
- Поиск курсов по названию.
- Фильтрация курсов по категории.
- Получение рекомендаций от ML-модели.
- Сохранение взаимодействий пользователей с курсами.
- Использование истории пользователя для персонализации.
- Автоматические тесты API.
- Запуск Backend через Docker.

## 2. Структура Backend

- main.py — FastAPI и обработчики запросов.
- init_db.py — создание базы и загрузка курсов.
- db.sqlite3 — локальная база данных.
- test_main.py — автоматические тесты.
- requirements.txt — зависимости приложения.
- requirements-dev.txt — зависимости для разработки и тестирования.
- Dockerfile — конфигурация Docker.

Дополнительные компоненты проекта:
- data/processed/courses.csv — подготовленный датасет.
- data/raw/ — исходные данные для ML.
- ml/main.py — рекомендательный алгоритм.

## 3. База данных

Используется SQLite.

Таблица courses:
- course_id — ID курса.
- title — название.
- category — категория.
- description — описание.
- university — университет.
- language — язык.
- directions — направления обучения.

Таблица interactions:
- user_id — ID пользователя.
- course_id — ID курса.
- weight — вес интереса пользователя.

Для повторного взаимодействия одного пользователя с одним курсом значение weight обновляется.

## 4. Запуск Backend локально

Все команды выполняются из корневой папки EduMath.

Установить зависимости:

```powershell
py -m pip install -r backend/requirements-dev.txt
```

Создать и заполнить базу данных:

```powershell
py backend/init_db.py
```

Запустить сервер:

```powershell
py -m uvicorn backend.main:app --reload
```

Документация API:

http://127.0.0.1:8000/docs

Для остановки сервера нажать Ctrl + C.

## 5. API

### GET /courses

Возвращает список реальных курсов из SQLite.

Дополнительные параметры:
- search — поиск по названию.
- category — фильтрация по категории.

Пример:

GET /courses?search=Python

### GET /recommendations

Возвращает до 10 курсов, рекомендованных ML-моделью.

Параметр:
- user_id — ID пользователя.

Пример:

GET /recommendations?user_id=1

Модель учитывает историю взаимодействий пользователя из SQLite.

Если истории нет, используются рекомендации без персонального профиля (cold start).

Ответ содержит:
- course_id
- title
- category
- score

### POST /interactions

Сохраняет интерес пользователя к курсу.

Пример JSON:

```json
{
  "user_id": 1,
  "course_id": 899,
  "weight": 1.0
}
```

Вес должен быть больше 0 и не превышать 1.

Если курса нет в базе, возвращается 404.
При некорректных данных возвращается 422.

При успешном сохранении возвращается статус saved.

## 6. ML-модель

Рекомендательный алгоритм находится в ml/main.py.

Backend получает взаимодействия пользователя из SQLite и передаёт их модели.

Модель формирует рекомендации на основе интересов пользователя и содержания курсов.

Уже отмеченные курсы исключаются из рекомендаций.

Данные для модели загружаются из data/raw/.

## 8. Docker

Для сборки нужны Backend, ML и необходимые файлы данных.

Команды выполняются из корня EduMath.

Сборка образа:

```powershell
docker build -f backend/Dockerfile -t edumath-backend .
```

Запуск контейнера:

```powershell
docker run --rm -p 8000:8000 --name edumath-api edumath-backend
```

Остановка:

```powershell
docker stop edumath-api
```

### Постоянное хранение SQLite

Сначала необходимо создать локальную базу с помощью init_db.py.

Запуск с подключением локальной SQLite:

```powershell
docker run --rm -d -p 8000:8000 --name edumath-api --mount "type=bind,source=$((Resolve-Path .\backend\db.sqlite3).Path),target=/app/backend/db.sqlite3" edumath-backend
```

В этом режиме взаимодействия сохраняются в файле backend/db.sqlite3 на компьютере.

Данные сохраняются после остановки и повторного запуска контейнера с тем же подключением.

- Убедиться, что данные Data Engineer включены в main.
- Проверить совместимость версий ML и Backend.
- Проверить API совместно с Frontend.
- Повторно запустить тесты и Docker.

Разработка ведётся в отдельной ветке.
Pull Request создаётся после согласования изменений с командой.
